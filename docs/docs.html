Make a Video With Your Agent

Facet comes in two parts that install together: the Facet Toolkit, the facet command that runs stateless media operations, and the Facet Bundle, the guidance that teaches your agent to use it. Your agentic CLI is the harness. It owns the model, tool calling, permissions, and memory; it plans the work and calls Facet's tools. You supply the idea or footage, approve consequential choices, and review the result.

Start with a simple request such as "Make a short explainer about how rain forms" or "Turn my screen recording into a concise walkthrough." You do not need to specify JSON, tool names, or a rigid production sequence.

Tool configuration, completed media generation, and editorial acceptance are separate checks.

Recommended Installation

Install Facet once for your user account, then wire it into the agentic CLIs you use: OpenCode, Codex, Claude Code, GitHub Copilot CLI, or Compa. Claude Code, Codex, and Copilot CLI can also add Facet as a plugin.

Run the command for your platform in a terminal:

# Windows (PowerShell)
irm https://kayiik.github.io/facet/install.ps1 | iex

# Linux / macOS
curl -fsSL https://kayiik.github.io/facet/install.sh | sh

The website bootstrap downloads the installer package pinned by version and SHA-256, checks its file list, then launches the installer. The Unix one-liner needs an interactive terminal for its prompts unless you pass --yes.

Windows builds Facet on your computer. Facet ships no prebuilt Windows binary. The installer instead builds facet.exe from the release's source with the official Go toolchain, after checking both downloads against pinned SHA-256 checksums. It then deletes Go and its build cache. This adds a minute or two and a 60-75 MB download. Go builds are reproducible: every computer builds the same file, and the release workflow checks that byte for byte. If Defender blocks facet.exe, please open an issue with the detection name. Do not turn off your antivirus.

The installer:

  • on Windows, builds facet.exe as described above; for an offline install, download the Go zip yourself and pass it with -ToolchainPath. On Linux and macOS it installs the prebuilt facet, or builds it the same way with --from-source (--toolchain FILE offline, or FACET_FROM_SOURCE=1 through the one-liner);
  • puts each runtime under ~/.facet/runtimes/<version>-<os>-<arch> and activates it as ~/.facet/current; set FACET_HOME to use another folder instead of ~/.facet;
  • adds ~/.facet/current/bin to your user PATH; opt out with -NoPath on Windows or --no-path on Linux and macOS;
  • installs FFmpeg and FFprobe with winget, Homebrew, or apt when they are missing;
  • installs the components you choose into the runtime: remotion and piper by default, hyperframes on request (on Windows, Piper is available for x64 only);
  • verifies FFmpeg and each selected component with a short test before it activates the runtime;
  • keeps the previous runtime for rollback and removes older ones; and
  • brings your recorded CLI wirings to the active runtime after every install, update, and rollback, and offers to wire more CLIs.

Installer actions are install, update, rollback, and uninstall, selected with -Action on Windows or --action on Linux and macOS. Uninstall removes the recorded CLI wirings, ~/.facet/current, and its PATH entry; installed runtimes are kept unless you add -Purge or --purge.

  1. Run the installer and review the optional components.
  2. Wire the CLIs you use, during setup or later with facet wire.
  3. Run facet doctor to check dependencies.
  4. Start a new session in your CLI and ask it to use Facet.

Your CLI keeps its own models and authentication; Facet does not configure them.

Installer Options

--action install|update|rollback|uninstall
--version VERSION
--components remotion,piper,hyperframes|all|none
--wire claude,codex,copilot,opencode,compa|all|none
--scope user|project
--project DIR
--yes   --no-path   --skip-verify   --purge

These are the Linux and macOS spellings. On Windows the options are -Action, -Version, -Components, -Wire, -Scope, -ProjectDir, -NonInteractive, -NoPath, -SkipVerify, and -Purge. --skip-verify skips the media checks and records the runtime as unverified.

With the one-liners, pass options after sh -s -- on Linux and macOS, or set them as environment variables on Windows: FACET_ACTION, FACET_VERSION, FACET_COMPONENTS, FACET_WIRE, FACET_SCOPE, and FACET_PROJECT take a value; FACET_YES, FACET_NO_PATH, FACET_SKIP_VERIFY, and FACET_PURGE take 1.

# Linux / macOS
curl -fsSL https://kayiik.github.io/facet/install.sh | sh -s -- --yes --wire claude

# Windows (PowerShell)
$env:FACET_YES = '1'; $env:FACET_WIRE = 'claude'
irm https://kayiik.github.io/facet/install.ps1 | iex

Manual Installation

Download facet-installer-<version>.zip from the release on GitHub, extract it, and run ./install.ps1 in PowerShell or bash ./install.sh from the extracted folder. Only the website bootstrap supports piping. To install from files you already downloaded, pass the release archive and SHA256SUMS.txt with -ArchivePath and -ChecksumPath (--archive and --checksums). On Windows that is the source archive, facet-<version>-source.zip, plus the Go zip with -ToolchainPath. On Linux and macOS it is facet-<version>-<os>-<arch>.zip, or the source archive with --toolchain. The installer checks each file against its SHA-256.

npm Launcher

The npm package @kayiik/facet only provides a facet command that starts an installed runtime: FACET_BIN when it is set, else current/bin/facet in Facet's home folder. It does not install the runtime; use the installer for that.

Production Runtime

Local editing and rendering do not require media-provider API keys. Edge TTS is built into Facet and uses a keyless network service; facet doctor does not test service reachability. Optional generation services may require separate credentials, account access, or credits.

  • FFmpeg and FFprobe: required for core media editing and inspection.
  • Remotion (default component): animated compositions and rendered captions, with Node.js, the composer's npm packages, and a headless browser.
  • Piper (default component): offline speech in a private Python environment, with the pinned voice en_US-lessac-medium.
  • HyperFrames (optional component): HTML-based video rendering, declared as using the network.
  • Edge TTS: preferred natural narration when network processing is acceptable; its client is built into Facet.
  • gflow: optional image and video generation through a separately supplied CLI.

Wire Your CLI

Wiring is your decision, like installing a skill or plugin. facet wire installs the Facet Bundle into the CLI's own locations: the facet skill, one facet-<pack> skill per production pack, and the facet-creative agent where the CLI supports agents. It registers the facet MCP server (the Facet executable started with mcp) through the CLI's own configuration, and adds rules to ask before the tools that may charge. It never edits instruction files such as AGENTS.md or CLAUDE.md.

facet wire <cli>[,<cli>...]|all [--scope user|project] [--project DIR] [--exe PATH] [--dry-run]
facet wire --remove <cli>[,<cli>...]|all [--scope user|project] [--project DIR] [--dry-run]
facet wire --refresh [--dry-run]
facet wire --status

<cli> is claude, codex, copilot, opencode, or compa; Compa is wired at user scope only, and all includes it only where Compa is set up. The default scope is your user account; --project wires one project (default: the current directory) and implies --scope project. --exe chooses the executable to register; by default it is current/bin/facet in Facet's home folder when that exists. --dry-run prints the exact actions without changing anything.

Everything facet wire writes is recorded in wiring.json in Facet's home folder. --status reports every wiring and any drift, --remove takes back only recorded items that are unchanged, and --refresh brings every recorded wiring to the running version; the installer runs it after every install, update, and rollback. Files that facet wire did not write, or that changed since, are never overwritten or deleted.

At project scope, Claude Code asks you to approve the project's MCP server the first time it starts there, and Codex reads a project's .codex/config.toml only for projects you have marked as trusted. Compa 0.0.1 or later is supported. Set it up with compa-kernel onboard first; facet wire compa follows COMPA_CONFIG and COMPA_HOME, edits config.json in one locked step, and checks the result with compa-kernel mcp list when it finds the kernel. Then restart or reload Compa's gateway. Compa's one-shot compa-kernel agent -m cannot answer an ask, so it refuses the paid tools.

Install as a Plugin

Claude Code, Codex, and Copilot CLI can add Facet from the plugin marketplace in Facet's repository instead of facet wire. A plugin carries the same skills and registers the facet MCP server, which runs the facet command from your PATH, so install the Toolkit first.

# Claude Code
claude plugin marketplace add kayiik/facet
claude plugin install facet@facet

# Codex
codex plugin marketplace add kayiik/facet
codex plugin add facet@facet

# Copilot CLI
copilot plugin marketplace add kayiik/facet
copilot plugin install facet@facet

The marketplace serves the plugins of the current release. Keep the plugin and the Toolkit at the same version (facet version prints the Toolkit's), and start a new session after installing. If the Toolkit is missing, the facet skill has your agent ask you to install it.

The Codex plugin asks before every paid tool, sets tool_timeout_sec = 600, and forwards the environment variables Facet reads. The Claude Code plugin asks before every paid tool through a hook. A plugin cannot add permission rules, so the hook runs facet hook claude before Facet's paid tools and before shell commands, and Claude Code asks even for a tool you have allowed. The hook needs a Toolkit of 0.0.1 or later; with an older one, Claude Code runs the tool without asking. Copilot CLI asks before every tool that is not read-only. Use the plugin or facet wire for a CLI, not both, since each registers its own facet server.

Paid Tools Ask First

Eight tools may charge: elevenlabs_tts, flux_image, gflow_image, gflow_video, kling_video, openai_image, openai_tts, and sora_video. facet tools list shows every tool's declared effects: may_charge, network, external_write, and deterministic.

Facet declares effects, facet wire turns them into your CLI's own approval settings, and your CLI enforces them. The rules come from the tools' may_charge declarations. In Claude Code they also cover facet tools run <tool> from the shell, and the Claude Code plugin does the same through a hook. Copilot CLI has no per-tool setting; in its default mode it asks before every Facet tool that is not read-only, which includes every paid tool. Facet itself never enforces consent, so check what your CLI is set to allow.

The Facet skill tells your agent to propose paid work, wait for your approval, and run paid tools only through MCP, where your CLI asks first. Unknown cost is not free.

A paid call cut off midway may already be charged and still running at the provider. kling_video and sora_video name their provider job as soon as the provider accepts it: in a progress message (on stderr from facet tools run), in the error of a call that ends without the video, and in the result and its artifact record. Run the same request again with "resume_job_id" set to that id to collect the job without submitting, and paying for, a new one. For gflow, read the error and any recovery_path it names before running the call again.

MCP and the Shell

Your agent reaches Facet over MCP by default. The server reports progress on long calls to CLIs that ask for it, and cancelling a call stops its processes. Some CLIs end an MCP call after a fixed time; Codex allows 60 seconds by default, so facet wire sets tool_timeout_sec = 600 for its facet server, and on Compa 0.0.1 or later it sets tools.mcp.call_timeout_seconds to 600 when you have not set it.

For renders that may take longer, an estimate reports prefer_shell: true, and the agent runs the same tool from the shell, in the background if your CLI allows it:

facet tools estimate video_compose --input request.json
facet tools run video_compose --input request.json

The Facet skill keeps paid tools on MCP, where your CLI asks first.

Upgrading from 1.x

Facet installs once per user, and wiring is a separate step.

  1. In each project that used the 1.x installer, run the v1.1.0 installer with --action uninstall (-Action uninstall on Windows). Download the v1.1.0 installer ZIP, extract it, and keep its installer/ directory beside the scripts; the v1.1.0 release lists its assets and SHA-256 checksums. The 1.x uninstall verifies ownership before it removes that project's managed Facet skill, state, and instruction section; modified and unmanaged content is kept.
  2. Install 2.0.
  3. Wire your CLIs with facet wire.

facet doctor reports 1.x installations in the current folder and your home folder whose skill copies would shadow the new skill, with the uninstall command for each. The 2.0 installer leaves 1.x runtimes in ~/.facet/releases untouched.

Removed in 2.0: facet ui, facet-ui, and the browser preview; facet init; facet module and facet-module; per-project launchers (run-facet); per-project installer receipts and managed instruction sections; the configuration files .facet.yaml and ~/.config/facet/config.yaml; the guidance, composer, and app files that the 1.x npm package carried (@kayiik/facet is now only a launcher); and the tool aliases audio_mixer and frame_sampler (use audio_mix and frame_sample).

Verify the Setup, Then Review the Work

Run facet doctor to check the active runtime, your wirings, leftover 1.x files, FFmpeg, Node.js and the Remotion composer, the agentic CLIs it finds, the provider keys that are set, and each tool's readiness. Run facet wire --status to see what is wired and whether anything drifted. These checks do not test external provider access or establish editorial quality.

Review the actual video, audio, captions, and source material from your production before sharing it.

Use Your Agent in the Terminal

Open your wired CLI in a production folder and ask it to use Facet.

Use Facet to make a short explainer about how rain forms.

Use a separate directory for each production. In your agent conversation, try "Add captions to my recording" or "Make the narration slower and leave more time on the diagram." Give it the actual source file location when editing existing media.

The agent proposes the method, voice, asset sources, and any cost before it generates or renders, and waits for your approval. Ask it to explain provider choices and costs before paid work, and to report errors without substituting placeholders. Number of turns, render duration, and final quality depend on the request and environment.

Choose a Production Pack

The Bundle installs the core facet skill and each of the following packs as its own skill. The facet skill directs your agent to the relevant pack for the task. A pack supplies guidance and content, not proof that every referenced tool or provider is installed.

Explainer / facet-explainer
Manifest: animated explainers, diagrams, charts, and text cards. Requires the Remotion component and a usable narration route when speech is requested.
Cinematic / facet-cinematic
Manifest: cinematic and documentary montages. Needs supplied or accessible source media with suitable rights; generated clips need configured providers.
Screen Demo / facet-screen-demo
Manifest: software walkthroughs and terminal scenes. Actual capture requires app access and recording/browser tooling; synthetic terminals must not be presented as real execution evidence.
Talking Head / facet-talking-head
Manifest: presenter edits and avatar workflows. Requires presenter footage or a separate avatar/lip-sync provider and consent. TTS alone does not generate a presenter.
Social / facet-social
Manifest: vertical clips and podcast repurposing. Needs source media and accurate transcript/timing data for captions. Framing and moment selection need review; audience performance is not guaranteed.
Character Animation / facet-character-animation
Manifest: rigs, pose libraries, and action timelines. Requires character assets, authoring, and a working renderer; no character-generation model is bundled by the pack.
Localization / facet-localization
Manifest: translated voiceovers, subtitles, and dubbing. Requires source media, transcription/translation, and a target-language voice. Voice cloning or lip-sync needs separate provider support and consent; check translation and timing.

Optional gflow Integration

Facet's gflow_image and gflow_video tools can call a separately supplied compatible gflow CLI. The public Facet installer does not distribute that private provider dependency. Its help and error diagnostics explain the requirements of the provider you configure.

Setup or status success is not generation evidence. Quotas, credits, account eligibility, models, and service availability still apply. Facet does not promise zero-cost generation; unknown estimates or zero-valued generic metadata are not a billing guarantee.

Dependency, authentication, provider, timeout, and invalid-response errors should be investigated, not hidden by mock output. An explicit mock: true request creates test media; it is never proof of provider generation. A timed-out request may still be running remotely, so check before retrying. When a failed run leaves downloaded media behind, Facet keeps its staging folder and names it as recovery_path in the error.

Project Files Are the Durable Record

Facet stores no workflow state. Scripts, scene plans, narration, renders, and review outputs appear only when the corresponding work runs.

my-video/
  assets/             # supplied or acquired media
  artifacts/          # scripts/plans/reports when produced
  narration/          # generated or supplied voice tracks
  renders/            # video and review outputs when produced

Media directories and paths such as renders/final.mp4 are conventions, not a promise that installation creates a video. Tool results describe each artifact by path, media type, size, SHA-256, tool, and version.

A tool writes the outputs a request names. When a request names none, the default output goes into the call's folder: the working directory for facet tools run, or the allowed root over MCP. Over MCP, relative paths resolve against the allowed root and paths outside it are refused. The root is the directory given by facet mcp --root; without it, the client's first root, or the working directory when the client supplies none.

There is no configuration file. Facet looks for the programs a runtime installed (Node.js, Piper, the Remotion composer, HyperFrames) beside its own executable first, and for other programs such as FFmpeg on your PATH, exactly as facet doctor reports them.

Using Facet with Another Agent

Using a different agent? Facet's tools are served over MCP by facet mcp, and its skills are plain Markdown. Ask your agent to inspect this repository and adapt the skills and the MCP server registration to its own conventions. facet wire supports the five CLIs listed above, and Claude Code, Codex, and Copilot CLI can also install Facet as a plugin; other integrations are community-adapted and may need additional setup.

Facet App

The Facet app is withdrawn in 2.0. The 1.x browser preview did not start from the release installer and has been removed, together with facet ui and facet-ui. A Facet App for people who do not use a terminal is planned as a separate download, with Facet's own window, an agent engine, and the Facet Bundle already wired in. Until then, use Facet through a supported agentic CLI.

Known Limitations

  • Installation is not acceptance. Local setup checks do not verify every workflow. Browser dependencies, fonts, and provider access can still affect a production.
  • Pack guidance is broader than the executable registry. Some routes reference optional tools, models, transcription, or browser integrations not supplied by the native CLI. Check the installed tool and its actual implementation before relying on it.
  • Network services are conditional. Edge TTS is keyless but network-dependent. Other providers may need credentials and payment; model availability and account limits can change.
  • Consent is enforced by your CLI, not by Facet. Facet declares each tool's effects; facet wire adds ask rules for paid tools where the CLI supports them, and your CLI's settings decide when you are asked.
  • The Facet app is withdrawn. Use Facet through a supported agentic CLI.
  • Automated review is partial. Technical media checks and sampled frames do not establish factual accuracy, language quality, consent, asset rights, or creative quality. Watch and listen to the output.

These pages do not certify a release or promise a finished video in a fixed number of turns or minutes.

Most users can stay with natural-language prompts. Integrators should inspect the installed CLI and source contracts rather than copy an assumed universal scene payload.

request.json must contain the fields accepted by the selected tool and operation; --input also accepts an inline JSON object. Every command prints one JSON envelope, and the exit status is zero when ok is true. Discover the tool catalog from the installed build rather than trusting a fixed count.
